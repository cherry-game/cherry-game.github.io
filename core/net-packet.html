网络数据包 ​

框架把「连接层」和「协议层」分开：连接器负责收发字节流，网络解析器（NetParser） 负责编解码、握手、心跳和消息路由。框架内置两种协议实现。

解析器导入路径报文头适用场景
Pomelonet/parser/pomelo4 字节默认方案，支持路由、握手、心跳、字典压缩
Simplenet/parser/simple8 字节轻量自定义协议，用 MID 匹配请求

Pomelo 协议 ​

Pomelo 协议是框架的默认方案，浏览器端可以直接使用 pomelo-client SDK。

报文结构 ​

包体 = 4 字节包头 + 包内容：

偏移长度字段说明
01 字节type包类型
13 字节length内容长度，大端序

因为长度字段只有 3 字节，单个包最大 1 << 24 = 16MB。

包类型 ​

类型值说明
None0x00空
Handshake0x01握手请求 / 握手响应
HandshakeAck0x02客户端握手确认
Heartbeat0x03心跳
Data0x04业务数据包
Kick0x05服务端踢下线

包大小限制 ​

默认读写上限都是 16MB，可以按需调整：

go
agentActor := pomelo.NewActor("user")
agentActor.SetReadMaxPacketSize(1 << 20)  // 读上限 1MB
agentActor.SetWriteMaxPacketSize(1 << 20) // 写上限 1MB

传入 <= 0 会回落到默认值 16MB。超出上限时读/写都会返回 PacketSizeExceed 错误。

调小要谨慎

上调上限等于放大了单个连接的攻击面。如果客户端可能发送超大包，建议调小而不是保留默认的 16MB。

解析器配置 ​

pomelo.Actor 提供的配置方法：

方法说明
AddConnector(conn)挂载连接器，可挂多个
SetSerializer(...)消息序列化方式
SetDictionary(...)设置路由字典（路由字符串压缩）
SetDataCompression(...)开启数据压缩
SetWriteBacklog(n)写缓冲队列长度
SetHeartbeat(d)心跳间隔
SetSysData(...)握手时下发的系统参数
SetOnNewAgent(fn)新连接建立回调
SetOnDataRoute(fn)数据路由回调
SetOnPacket(fn)收到包的回调
SetReadMaxPacketSize(size)读包大小上限
SetWriteMaxPacketSize(size)写包大小上限

消息路由 ​

Pomelo 的路由字符串是三段式，由 . 分隔：

room.room.login
└─┬─┘ └─┬─┘ └─┬─┘
  │     │     └── 方法名
  │     └──────── handle 名，对应 Actor 的 AliasID
  └────────────── 节点类型

DefaultDataRoute 的处理逻辑：

  1. 如果 route.NodeType() 与当前节点类型相同 —— 消息投给本地 Actor，路径为 <节点id>.<handle>.<sid>
  2. 否则查发现服务，随机选一个该类型的节点，经 ClusterLocalDataRoute 通过 NATS 投递过去
go
// 本地投递
func LocalDataRoute(agent *Agent, route *pmessage.Route, msg *pmessage.Message, targetPath string)

// 跨节点投递
func ClusterLocalDataRoute(agent *Agent, route *pmessage.Route, msg *pmessage.Message, nodeID, targetPath string) error

版本变化

从 v1.6.8 起，pomelo 的 DefaultDataRoute、LocalDataRoute、ClusterLocalDataRoute 都移除了 session 参数 —— session 现在从 agent.NewSession(msg.ID) 内部构造。

两个协议的参数顺序不同

两个解析器的 DefaultDataRoute 都接收 (agent, route, msg) 或 (agent, msg, route)，顺序正好相反：

go
// pomelo
func DefaultDataRoute(agent *Agent, route *pmessage.Route, msg *pmessage.Message)

// simple
func DefaultDataRoute(agent *Agent, msg *Message, route *NodeRoute)

路由对象的类型也不同（pmessage.Route vs NodeRoute）。从旧版本升级或跨协议移植代码时容易搞混，注意区分。

自定义路由 ​

go
agentActor.SetOnDataRoute(func(agent *pomelo.Agent, route *pmessage.Route, msg *pmessage.Message) {
	if route.Method() == "login" {
		// 登录消息投给三段式路径，每个连接一个子 Actor
		targetPath := cfacade.NewChildPath(agent.NodeID(), route.HandleName(), agent.SID())
		pomelo.LocalDataRoute(agent, route, msg, targetPath)
		return
	}

	if !agent.IsBind() {
		agent.ResponseCode(session, ccode.SessionUIDNotBind, true)
		return
	}

	// 其余消息投给两段式路径，由父 Actor 统一处理
	targetPath := cfacade.NewPath(agent.NodeID(), route.HandleName())
	pomelo.LocalDataRoute(agent, route, msg, targetPath)
})

Simple 协议 ​

Simple 是轻量协议，用 MID 直接匹配请求与响应，适合自研客户端。

报文结构 ​

包体 = 8 字节包头 + 包内容：

偏移长度字段说明
04 字节MID消息 id，用于请求应答匹配
44 字节DataLen内容长度
8DataLenData包内容

字节序可配置，默认大端。

4KB 上限

simple 协议的 payload 上限是硬编码的 4096 字节，没有 setter。超过会返回 PacketSizeExceed。需要传大包请改用 pomelo 协议。

使用方式 ​

simple 用 mid → NodeRoute 的映射表来路由，而不是解析路由字符串：

go
type NodeRoute struct {
	NodeType string // 目标节点类型
	ActorID  string // 目标 Actor id
	FuncName string // 目标函数名
}

// 注意接收的是指针
agentActor.AddNodeRoute(mid, &NodeRoute{
	NodeType: "game",
	ActorID:  "player",
	FuncName: "enter",
})

解析器配置方法：

方法说明
AddConnector(conn)挂载连接器
AddNodeRoute(mid, *NodeRoute)注册 mid → 路由的映射，参数是指针
SetOnDataRoute(fn DataRouteFunc)自定义数据路由
SetHeartbeatTime(d)心跳间隔
SetWriteBacklog(n)写缓冲队列长度
SetEndian(order)字节序，默认大端
SetOnNewAgent(fn)新连接建立回调

路由函数的 session 差异 ​

DefaultDataRoute 在两个协议里都不接收 session 参数，由内部 agent.NewSession(...) 构造。但底层投递函数的签名不同：

go
// pomelo：v1.6.8 起已移除 session
func LocalDataRoute(agent *Agent, route *pmessage.Route, msg *pmessage.Message, targetPath string)
func ClusterLocalDataRoute(agent *Agent, route *pmessage.Route, msg *pmessage.Message, nodeID, targetPath string) error

// simple：仍然接收 session
func LocalDataRoute(agent *Agent, session *cproto.Session, msg *Message, nodeRoute *NodeRoute, targetPath string)
func ClusterLocalDataRoute(agent *Agent, session *cproto.Session, msg *Message, nodeRoute *NodeRoute, nodeID, targetPath string) error

自定义路由时如果直接调用这两个函数，注意按对应协议的签名传参——simple 需要自己先构造 session := agent.NewSession(msg.MID)。

消息序列化 ​

框架自带两种序列化方式：

序列化说明
JSON可读性好，浏览器端调试方便
Protobuf体积小、速度快，生产环境推荐
go
import cserializer "github.com/cherry-game/cherry/net/serializer"

// 网页调试用 JSON（默认是 protobuf）
app.SetSerializer(cserializer.NewJSON())

跨节点报文 ​

节点之间的 Actor 消息由框架序列化成 ClusterPacket 传输：

字段说明
buildTime消息构造时间
sourcePath来源 Actor 路径
targetPath目标 Actor 路径
funcName调用的方法名
argBytes序列化后的参数
session会话数据

这部分业务代码无需感知，由 集群组件 自动处理。
