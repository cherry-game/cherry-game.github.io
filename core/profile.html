Profile 配置 ​

Profile 是 Cherry 唯一的配置文件，格式为 JSON。框架自身的参数、每个组件的参数、每个节点私有的业务参数，全部通过它管理。

特点 ​

  • 多环境：同一份配置里可以声明多套环境，通过 env 切换
  • 可拆分：用 include 把配置拆成多个子文件，按需组合，避免重复
  • 按节点隔离：每个节点只读取属于自己的那段配置，__settings__ 存放节点私有参数
  • 类型安全读取：提供带默认值的类型化读取方法，避免到处手写类型断言

加载配置 ​

go
app := cherry.Configure(
	"./config/profile.json", // profile 文件路径
	"game-1",                // 节点 id
	false,                   // 是否前端节点
	cherry.Cluster,          // 节点模式
)

框架在 Configure 时完成加载：

  1. 读取主配置文件
  2. 读取 include 列出的子文件并深度合并（主配置覆盖子配置的同名键）
  3. 按 nodeID 从 node 段中找出对应节点

相对路径

Configure 的文件路径是相对于进程工作目录的。上面的例子要求从 game-1 所在目录启动进程。示例仓库统一用 ../../config/xxx.json 这种相对路径，所以必须在对应的子目录里执行 go run .。

合并规则 ​

json
{
    "include": [
        "include/logger.json",
        "include/demo-data-config.json"
    ],
    "env": "dev",
    "debug": true
}

合并顺序：

  1. 主配置文件读入 profileMaps
  2. include 列出的文件依次读入 includeMaps
  3. 先把 includeMaps 合并进根，再把 profileMaps 合并进根

结果就是：主配置的键覆盖 include 文件的同名键，深层的对象是逐键合并而不是整体替换。所以可以把日志、组件配置拆出去公用，主配置只写差异部分。

全局参数 ​

参数类型默认值说明
envstringdefault当前环境标识
debugbooltrue是否调试模式
print_levelstringdebug控制台日志级别

节点配置 ​

node 段按节点类型分组，每个类型下是一个节点数组：

json
{
    "node": {
        "master": [
            { "node_id": "gc-master", "enabled": true, "__settings__": { "ref_logger": "master_log" } }
        ],
        "gate": [
            { "node_id": "^gc-gate-\\d+$", "address": ":10010", "enabled": true }
        ],
        "game": [
            { "node_id": "^\\d+$", "enabled": true }
        ]
    }
}

节点字段：

字段类型说明
node_idstring / array节点标识，支持三种匹配方式
addressstring监听地址，如 :10010、127.0.0.1:8081
rpc_addressstring跨节点 RPC 地址
__settings__object节点私有参数
enabledbool是否启用

node_id 的三种匹配方式 ​

框架按顺序尝试：

方式写法用途
精确匹配"game-1"固定节点
正则匹配"^gc-gate-\\d+$"需要以 ^ 开头、$ 结尾才被识别为正则
数组包含["game-1", "game-2"]少量固定节点共用一个配置块

正则匹配是横向扩展的关键：gate 和 game 节点都写成正则，这样加机器时不用改配置，直接用新的 --node 参数启动即可。

settings 节点私有参数 ​

每个节点的差异化参数放在 __settings__ 里，业务代码通过 App().Settings() 读取：

json
{
    "node_id": "gc-gate-1",
    "address": ":10010",
    "__settings__": {
        "ref_logger": "gate_log",
        "db_id_list": {
            "game_db_id": "game_db_1"
        }
    }
}
go
// 读取字符串
loggerName := app.Settings().GetString("ref_logger")

// 读取子对象
dbID := app.Settings().GetConfig("db_id_list").GetString("game_db_id")

读取配置 ​

类型安全读取 ​

框架提供带默认值的类型化读取方法，全部挂在 ProfileJSON 接口上：

go
cfg := cprofile.GetConfig("logger").GetConfig("game_log")

level    := cfg.GetString("level", "info")
enabled  := cfg.GetBool("enable_console", true)
maxAge   := cfg.GetInt("max_age", 7)
timeout  := cfg.GetDuration("timeout", 3*time.Second)

var myStruct MyConfig
err := cfg.Unmarshal(&myStruct)

可用方法：GetString、GetBool、GetInt、GetInt32、GetInt64、GetUint*、GetFloat*、GetDuration、Unmarshal。

GetDuration 返回纳秒

GetDuration 返回的是原始的纳秒时长，需要自己乘单位。传 3*time.Second 作为默认值是安全的，因为 time.Second 本身也是纳秒计数。

框架内部读取 ​

go
import cprofile "github.com/cherry-game/cherry/profile"

cfg := cprofile.GetConfig("cluster").GetConfig("nats")
prefix := cfg.GetString("prefix", "node")

用 LastError() 可以判断路径是否存在：

go
natsConfig := cprofile.GetConfig("cluster").GetConfig("nats")
if natsConfig.LastError() != nil {
	panic("cluster->nats config not found.")
}

logger ​

按名称定义多个日志配置，节点通过 __settings__.ref_logger 引用其中一个：

json
{
    "logger": {
        "game_log": {
            "level": "debug",
            "stack_level": "error",
            "encoder_type": "console",
            "enable_console": true,
            "enable_write_file": true,
            "max_age": 7,
            "time_format": "2006-01-02 15:04:05.000",
            "print_caller": true,
            "rotation_time": 86400,
            "file_link_path": "./logs/game.log",
            "file_path_format": "./logs/%Y%m%d/game.log",
            "include_stdout": true,
            "include_stderr": true
        }
    }
}
字段说明
level最低启用的日志级别
stack_level达到该级别时记录堆栈
encoder_type编码类型：console（key=value）或 json
enable_console是否同步写入标准错误
enable_write_file是否写文件（带轮转）
max_age日志保留天数
rotation_time文件切割周期，单位秒（上例为 1 天）
time_format时间戳格式
print_caller是否在每行打印调用位置
file_link_path指向当前日志文件的固定软链接名
file_path_format切割后的文件路径模板（strftime 语法）
include_stdout / include_stderr额外挂载标准输出 / 标准错误
