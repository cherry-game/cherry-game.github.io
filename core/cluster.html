通信 & 集群 ​

Cherry 的所有节点通过 NATS 通信。跨节点调用、节点发现、RPC 回包都建立在 NATS 之上，框架已经把这层封装好，业务代码只需操作 Actor 路径。

  • 传输层：固定使用 NATS，ICluster.Mode() 返回 "nats"
  • 发现服务：三种实现可选 —— default（读本地配置）/ nats（主从心跳）/ etcd（分布式）
  • 调用方式：同步 / 异步 RPC，以及原始 subject 的发布与请求

集群组件 ​

接口定义在 facade/cluster.go：

go
type ICluster interface {
	Mode() string // 传输模式，当前为 "nats"

	PublishLocal(nodeID string, msg *Message) error        // 投递到本节点，不序列化
	PublishRemote(nodeID string, msg *Message) error       // 投递到指定远程节点
	PublishRemoteType(nodeType string, msg *Message) error // 投递到某类型的随机节点

	RequestRemote(nodeID string, msg *Message, timeout ...time.Duration) ([]byte, int32)
	RequestSync(subject string, data []byte, timeout ...time.Duration) ([]byte, error)
	RequestReply(reqID, replySubject string, data []byte) error

	RawPublish(subject string, data []byte) error
	RawRequest(subject string, data []byte, timeout ...time.Duration) ([]byte, error)
}
方法说明
PublishLocal消息在本进程内传递，不序列化，开销最小
PublishRemote序列化后经 NATS 发到指定 nodeID
PublishRemoteType发到某节点类型下随机一个节点，用于负载均衡
RequestRemote发出并等待应答，返回原始 payload + 状态码
RequestSync面向已知 subject 的请求应答，不做发现查询；reqID 由内部生成
RequestReply低层封装，用来把应答发回请求方（replySubject + reqID 头）
RawPublish / RawRequest直接对原始 subject 收发，用于和外部服务对接

PublishLocal vs PublishRemote

同一个 subject 上，「local」指本进程投递、「remote」指跨进程投递。PublishLocal(nodeID, msg) 里的 nodeID 仍然是必填的——框架靠它校验目标节点。

NATS Subject 格式 ​

cherry-{prefix}.local.{nodeType}.{nodeID}
cherry-{prefix}.remote.{nodeType}.{nodeID}
cherry-{prefix}.remoteType.{nodeType}
cherry-{prefix}.reply.{nodeType}.{nodeID}

prefix 来自 cluster.nats.prefix，默认 node。比如节点 gc-gate-1（类型 gate）订阅的 remote subject 是：

cherry-node.remote.gate.gc-gate-1

集群组件使用两个独立连接：publishConnect（发送 / 请求 / 应答）和 subscribeConnect（订阅）。应答通过每条连接的专用 reply subject 匹配，超时后迟到的应答会被丢弃，不会串到下一个请求。

发现服务 ​

接口定义在 facade/cluster.go：

go
type IDiscovery interface {
	Mode() string
	Map() map[string]IMember
	ListByType(nodeType string, filterNodeID ...string) []IMember
	Random(nodeType string) (IMember, bool)
	GetMember(nodeID string) (member IMember, found bool)
	UpdateSetting(key, value string)
	UpdateSettings(settings map[string]string)
	OnAddMember(listener MemberListener)
	OnUpdateMember(listener MemberListener)
	OnRemoveMember(listener MemberListener)
}

三种模式 ​

模式mode 值适用场景
本地配置default单进程开发、测试，直接读 profile 里的节点表，无需额外部署
NATS 主从nats多节点生产环境，业务只需部署 NATS
etcdetcd多节点生产环境，依赖 etcd 集群，见 etcd 组件

default 模式 ​

节点信息直接写在 profile 里，不需要任何额外服务：

json
{
    "cluster": {
        "discovery": {
            "mode": "default"
        }
    },
    "node": {
        "game": [
            {
                "node_id": "game-1",
                "rpc_address": "127.0.0.1:10001",
                "__settings__": { "region": "us-west" }
            }
        ],
        "gate": [
            {
                "node_id": "gate-1",
                "rpc_address": "127.0.0.1:20001"
            }
        ]
    }
}

nats 模式 ​

指定一个节点作为 master，其余节点向它注册并定期心跳：

json
{
    "cluster": {
        "discovery": { "mode": "nats" },
        "nats": {
            "prefix": "node",
            "master_node_id": "master-1"
        }
    }
}

master_node_id 必须与真正跑 master 的那个节点的 node_id 一致。

启动顺序

master 节点必须最先启动。worker 启动时会向 master 发起注册请求，master 不在则拿不到成员列表。

NATS 模式的通信流程 ​

1. 启动 master 节点
2. Worker 启动 → NATS Request → master 收到 register
3. Master 回复完整成员列表 + NATS Publish 广播 add
4. Worker 定期心跳(1s) → master 心跳超时(3s) → 移除该成员并广播 remove
5. Worker 退出 → NATS Publish remove → 所有节点移除该成员

发现服务的 subject 格式：cherry.{prefix}.discovery.{masterID}.{type}

type方向说明
registerWorker → Master注册请求，携带自身成员数据
addMaster → Worker新成员广播
update双向Settings 变更广播
remove双向成员移除广播
heartbeatWorker → Master心跳；master 据此更新 LastAt，或回复 registerRequired 要求重新注册

业务层用法 ​

go
discovery := app.Discovery()

// 成员查询
all := discovery.Map()                        // 所有成员
games := discovery.ListByType("game")         // 按类型过滤
others := discovery.ListByType("gate", app.NodeID()) // 排除自己
member, ok := discovery.Random("gate")        // 随机取一个
member, ok := discovery.GetMember("game-1")   // 按 nodeID 查找

// Settings 同步：更新当前节点，自动同步到其它节点
discovery.UpdateSetting("region", "us-east")
discovery.UpdateSettings(map[string]string{"region": "us-east", "zone": "a"})

// 成员变更监听
discovery.OnAddMember(func(member cfacade.IMember) {
    // 新节点加入
})
discovery.OnRemoveMember(func(member cfacade.IMember) {
    // 节点离开
})

IMember 提供：

go
type IMember interface {
	GetNodeID() string              // 唯一节点标识
	GetNodeType() string            // 节点类型（game / gate / map ...）
	GetAddress() string             // 跨节点通信用地址
	GetSettings() map[string]string // 节点元数据
}

自定义发现服务后端 ​

接口是开放的，两种实现方式：

方式一：直接实现 IDiscovery

go
type MyDiscovery struct {
	cfacade.Component
}

func (m *MyDiscovery) Mode() string { return "my-mode" }
func (m *MyDiscovery) Init() { /* ... */ }
// ... 实现 IDiscovery 的全部方法

方式二：组合 ComponentDefault（推荐）

复用成员存储和 listener 通知逻辑，只关注传输层：

go
type MyDiscovery struct {
	cherryDiscovery.ComponentDefault
	thisMember *cproto.Member
}

func (m *MyDiscovery) Mode() string { return "my-mode" }

func (m *MyDiscovery) Init() {
	m.thisMember = cherryDiscovery.NewMemberWithApp(m.App())
	m.AddMember(m.thisMember)
	// 初始化传输层...
}

func (m *MyDiscovery) UpdateSetting(key, value string) {
	m.thisMember.UpdateSetting(key, value)
	// 通过传输层广播变更...
}

注册到框架：

go
func init() {
	cherryDiscovery.Register(&MyDiscovery{})
}

或者通过 builder 指定：

go
app := cherry.Configure(path, nodeID, false, cherry.Cluster)
app.SetDiscovery(cherryETCD.New())
app.Startup()

Startup() 内部会读取 cluster.discovery.mode，按名字从注册表查出对应实现。

配置参考 ​

cluster.discovery ​

参数类型默认值说明
modestring—发现服务模式：default / nats / etcd

cluster.nats ​

参数类型默认值说明
addressstring—NATS 服务地址，如 nats://127.0.0.1:4222，为空会报错
prefixstringnodeNATS subject 前缀
master_node_idstring—master 节点 ID，须与运行 master 的节点 node_id 一致
reconnect_delayint1重连间隔（秒）
request_timeoutint1请求超时（秒）
max_reconnectsint0最大重连次数，0 表示不限
userstring""NATS 用户名
passwordstring""NATS 密码
is_statsboolfalse是否输出连接统计日志
stats_intervalint30统计日志间隔（秒）

完整示例：

json
{
    "cluster": {
        "discovery": { "mode": "nats" },
        "nats": {
            "prefix": "node",
            "master_node_id": "gc-master",
            "address": "nats://127.0.0.1:4222",
            "reconnect_delay": 1,
            "max_reconnects": 0,
            "request_timeout": 2,
            "user": "",
            "password": ""
        }
    }
}

连接统计日志

把 is_stats 打开后，框架会按 stats_interval 周期输出 NATS 连接状况：MaxPayload、InMsgs、OutMsgs、InBytes、OutBytes、Reconnects。排查「消息发出去了但对方没收到」这类问题时很有用。
