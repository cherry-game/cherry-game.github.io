Actor 模型 ​

Cherry 的 Actor 模型建立在 Goroutine 之上：每个 Actor 独占一个 goroutine，天然串行地处理自己的消息。这让业务逻辑可以放心地读写 Actor 内部状态，不需要加锁。

核心特性 ​

  • 每个 Actor 独立运行在一个 goroutine 中，所有逻辑串行处理，Actor 内部状态无需加锁
  • Actor 可以创建多个子 Actor（ChildActor），子 Actor 与父 Actor 共享同一个 goroutine
  • 依托 Goroutine 的轻量特性，单个节点可以创建成千上万个 Actor
  • 通过集群组件与发现服务，支持跨节点 Actor 通信

消息队列 ​

每个 Actor 有 三条消息队列 和一条独立的定时器通路，各自 FIFO 消费：

通路队列名用途
本地消息local接收本节点投递的消息，如客户端请求经路由后的投递
远程消息remote接收 Actor 之间的 RPC 调用
事件消息event订阅/发布模式的事件通知
定时器—定时回调，走独立的 timer 通道

一个重要细节

同一个节点内 Actor 之间的 Call / CallWait 也走 remote 队列，而不是 local。只有 PostLocal 才走 local 队列。

Actor 接口 ​

生命周期与路由回调 ​

实现 IActorHandler 定义一个 Actor：

go
type IActorHandler interface {
	AliasID() string                          // Actor 注册使用的 ID
	OnInit()                                  // 消息循环开始前调用一次，在这里注册处理方法
	OnStop()                                  // goroutine 退出前调用一次，释放资源
	OnLocalReceived(m *Message) (bool, bool)  // 返回 (next, invoke)
	OnRemoteReceived(m *Message) (bool, bool) // 返回 (next, invoke)
	OnFindChild(m *Message) (IActor, bool)    // 从消息的 Target 路径解析子 Actor
}

生命周期顺序：AliasID() → OnInit() → [消息循环] → OnStop()

OnLocalReceived / OnRemoteReceived 的返回值 ​

这两个回调返回两个 bool，含义是 (next, invoke)：

返回值含义
invoke = true在本 Actor 上立即调用消息注册的处理函数
next = true继续往下走 —— 根据消息的 Target 路径决定是否转发给子 Actor

框架里是这么用的：

go
next, invoke := p.handler.OnLocalReceived(m)
if invoke {
	p.invokeFunc(p.localMail, p.App(), p.system.localInvokeFunc, m)
}
if !next {
	return // 不再转发给子 Actor
}

Base 的默认实现是 (true, false)：不自动调用处理函数，但继续向子 Actor 转发。

聊天室示例返回 (false, true)，表示「由房间 Actor 自己处理，不再往下转发」：

go
func (*actorRoom) OnLocalReceived(_ *cfacade.Message) (bool, bool) {
	return false, true
}

接口注释是旧的

facade/actor.go 里 IActorHandler 的注释把这组返回值描述为 (handled, needRecycle)，这是过时的说明，以实际实现 (next, invoke) 为准。

编写一个 Actor ​

嵌入 cactor.Base（在 net/actor/actor_base.go）可以只实现需要的方法：

go
import (
	cactor "github.com/cherry-game/cherry/net/actor"
	cfacade "github.com/cherry-game/cherry/facade"
)

type actorRoom struct {
	cactor.Base
	userMap map[int64]*User // 只被本 Actor 的 goroutine 访问，无需加锁
}

// AliasID 决定 Actor 路径：<节点id>.<aliasID>，例如 room-1.room
func (p *actorRoom) AliasID() string {
	return "room"
}

func (p *actorRoom) OnInit() {
	p.userMap = make(map[int64]*User)

	// 客户端消息走 Local 队列
	p.Local().Register("login", p.login)
	p.Local().Register("syncMessage", p.syncMessage)

	// 被 Call / CallWait 调用走 Remote 队列
	p.Remote().Register("exit", p.exit)

	// 不再把消息转发给子 Actor
}

func (p *actorRoom) OnLocalReceived(_ *cfacade.Message) (bool, bool) {
	return false, true
}

注册 Actor ​

go
app := cherry.Configure(path, "room-1", true, cherry.Standalone)
app.AddActors(&actorRoom{})
app.Startup()

Actor 的访问路径由「节点 id + AliasID」组成：

room-1.room          // 节点 room-1 上的 room actor
10001.player          // 节点 10001 上的 player actor

三种消息通路 ​

Local() / Remote() / Event() / Timer() / Child() 是 Actor 的门面访问器。

Local — 本地消息 ​

go
p.Local().Register("login", p.login)       // 注册处理函数
p.Local().Register("syncMessage", p.syncMessage)

Remote — 远程调用 ​

go
p.Remote().Register("exit", p.exit)

Event — 事件订阅 ​

go
p.Event().Register("eventName", p.onEvent)
p.Event().Registers([]string{"evtA", "evtB"}, p.onEvent)
p.Event().Unregister("eventName")

事件的载荷实现 IEventData：

go
type IEventData interface {
	Name() string    // 事件名，用于订阅匹配
	UniqueID() int64 // 去重标识，相同 ID 视为同一次事件
}

用 app.ActorSystem().PostEvent(data) 广播。

调用其它 Actor ​

go
// 异步调用，不等结果
actor.Call(targetPath, "funcName", arg)

// 同步调用，等待结果
var reply SomeType
code := actor.CallWait(targetPath, "funcName", arg, &reply)

// 调用某个节点类型上随机一个 Actor
actor.CallType("game", "player", "funcName", arg)

返回值是框架的状态码（cherryCode），不是业务错误码。

超时默认值：

参数默认值设置方法
RPC 调用超时3 秒ActorSystem().SetCallTimeout(d)
消息到达超时100 毫秒ActorSystem().SetArrivalTimeout(ms)
处理函数执行超时100 毫秒ActorSystem().SetExecutionTimeout(ms)

子 Actor ​

父 Actor 可以创建子 Actor，子 Actor 与父 Actor 共享同一个 goroutine——所有回调都是串行的，子 Actor 的处理函数之间、以及和父 Actor 之间都不会并发执行。

go
type IActorChild interface {
	Create(id string, handler IActorHandler) (IActor, error)
	Get(id string) (IActor, bool)
	Remove(id string)
	Each(fn func(i IActor))
	Call(childID, funcName string, arg any)
	CallWait(childID, funcName string, arg, reply any) int32
}

典型用法——为每条客户端连接创建一个子 Actor：

go
agentActor.SetOnNewAgent(func(newAgent *pomelo.Agent) {
	childActor := &ActorAgent{}
	newAgent.AddOnClose(childActor.onSessionClose)
	agentActor.Child().Create(newAgent.SID(), childActor) // 用 session id 作为子 Actor id
})

WARNING

子 Actor 不能再创建孙 Actor（actor_child.go 中会返回错误）。需要多层结构时，改成在父 Actor 里维护一个 map。

默认情况下父 Actor 会把收到的消息按路径转发给子 Actor。覆写 OnLocalReceived / OnRemoteReceived 返回 (false, true) 可以阻止转发。

定时器 ​

Actor 的定时器回调经过队列回到 Actor 自己的 goroutine 执行，所以回调里可以安全访问 Actor 内部状态。

go
type ITimer interface {
	New(d time.Duration, fn func()) ITimerHandle                        // 创建周期定时器，不启动
	NewOnce(d time.Duration, fn func()) ITimerHandle                    // 创建一次性定时器，不启动
	Add(d time.Duration, fn func()) ITimerHandle                        // 创建并启动周期定时器
	AddOnce(d time.Duration, fn func()) ITimerHandle                    // 创建并启动一次性定时器
	AddFixedHour(hour, minute, second int, fn func()) ITimerHandle      // 每天固定时刻
	AddFixedMinute(minute, second int, fn func()) ITimerHandle          // 每小时固定时刻
	AddSchedule(s ITimerSchedule, f func()) ITimerHandle                // 自定义调度
	Remove(id uint64)
	RemoveAll()
}
go
func (p *ActorDB) OnInit() {
	p.Timer().Add(5*time.Second, p.selectDB)     // 每 5 秒执行一次
	p.Timer().AddOnce(1*time.Second, p.once)     // 1 秒后执行一次
}

ITimerHandle 可以在运行时控制定时器，SetNext 可以动态改变下一次的间隔（返回 <=0 则停止）：

go
type ITimerHandle interface {
	ID() uint64
	Start()                          // 启动或重启
	Stop()                           // 停止
	IsOnce() bool
	IsRunning() bool
	SetNext(fn func() time.Duration) // 替换下一次延迟
}

底层是时间轮实现。全局时间轮参数可以调整，必须在启动前设置：

go
app.ActorSystem().SetTimerTick(10 * time.Millisecond) // 默认 10ms
app.ActorSystem().SetTimerHint(1024)                  // 预分配提示，默认 1024

TIP

AddFixedHour / AddFixedMinute 适合「每天凌晨 4 点」「每小时整点」这类业务，比用 cron 表达式更直接。需要完整 cron 语义请用 cron 组件。

Actor 系统 API ​

go
type IActorSystem interface {
	GetIActor(id string) (IActor, bool)
	CreateActor(id string, handler IActorHandler) (IActor, error)
	PostRemote(m *Message) bool
	PostLocal(m *Message) bool
	PostEvent(data IEventData)
	Call(source, target, funcName string, arg any) int32
	CallWait(source, target, funcName string, arg, reply any) int32
	CallType(nodeType, actorID, funcName string, arg any) int32
	SetLocalInvoke(invoke InvokeFunc)
	SetRemoteInvoke(invoke InvokeFunc)
	SetCallTimeout(d time.Duration)
	SetArrivalTimeout(t int64)
	SetExecutionTimeout(t int64)
	SetTimerTick(d time.Duration)
	SetTimerHint(n int)
}

业务代码通过 app.ActorSystem() 获取。

跨节点通信 ​

Actor 之间的跨节点调用由 集群组件 和 发现服务 承载：调用方序列化消息，通过 NATS 投递到目标节点，再交给目标 Actor 的 remote 队列。

整个业务代码不需要关心目标是本地还是远程——Call / CallWait 会根据目标路径自动选择走 local 还是 remote。
