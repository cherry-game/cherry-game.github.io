组件管理 ​

Cherry 用「组件」来组织和扩展框架能力。所有功能——集群通信、发现服务、Actor 系统、日志、数据库、HTTP 服务——都是组件。你的业务代码只需要把组件注册进去，框架会统一管理它们的生命周期。

为什么用组件 ​

  • 统一生命周期：框架负责在正确的时机调用 Init / OnAfterInit / OnStop，你不用自己维护启动顺序
  • 按需组合：单机模式只注册需要的组件，集群模式加上集群和发现组件
  • 易于扩展：实现 IComponent 接口即可接入框架，也能和框架自带组件互相依赖

组件接口 ​

接口定义在 facade/component.go：

go
type IComponent interface {
	Name() string      // 组件在 Application 内的唯一名称
	App() IApplication // 所属的 Application
	IComponentLifecycle
}

type IComponentLifecycle interface {
	Set(app IApplication) // 注入 Application 引用
	Init()                // 初始化内部状态
	OnAfterInit()         // 所有组件的 Init 都执行完后调用
	OnBeforeStop()        // 关闭流程开始前调用
	OnStop()              // 释放资源
}

生命周期 ​

启动：Set → Init → OnAfterInit
关闭：OnBeforeStop → OnStop
阶段时机适合做什么
Set(app)注册后最先调用，按注册顺序拿到 App() 引用
Init()按注册顺序依次执行初始化自己的状态、连接、监听端口
OnAfterInit()所有组件 Init 完成后通过 App().Find(name) 访问其它组件
OnBeforeStop()收到退出信号后停止接收新请求、flush 待写数据
OnStop()所有 OnBeforeStop 执行完，逆序关闭连接、释放资源

关键区别

Init() 里不要依赖别的组件——此时它们可能还没初始化。需要跨组件协作就放到 OnAfterInit()。

组件按注册顺序初始化、逆序关闭，所以依赖方要先注册，被依赖方后注册。

编写自定义组件 ​

嵌入 facade.Component 可以只覆写关心的方法，其余走空实现：

go
import (
	"github.com/cherry-game/cherry"
	cfacade "github.com/cherry-game/cherry/facade"
)

type MyComponent struct {
	cfacade.Component
	counter int
}

// Name 返回组件唯一名称
func (p *MyComponent) Name() string {
	return "my_component"
}

func (p *MyComponent) Init() {
	p.counter = 0
}

func (p *MyComponent) OnAfterInit() {
	// 此时所有组件的 Init 都已完成，可以安全地取其它组件
	other, ok := p.App().Find("some_component").(*SomeComponent)
	if !ok {
		return
	}
	_ = other
}

func (p *MyComponent) OnStop() {
	// 释放资源
}

注册到框架 ​

组件通过 app.Register(...) 注册，在 Startup() 之前调用：

go
func main() {
	app := cherry.Configure(
		"./config/profile.json", // profile 配置文件路径
		"game-1",                // 节点 id
		false,                   // 是否前端节点（true 才能使用 connector）
		cherry.Standalone,       // 节点模式
	)

	app.Register(
		&MyComponent{},
		cherryCron.New(),        // 也可以一次注册多个
	)

	app.Startup()
}

运行模式 ​

模式常量说明
集群模式cherry.Cluster框架自动注册集群组件和发现服务组件，支持跨节点通信
单机模式cherry.Standalone不注册集群与发现组件，适合单进程开发调试
go
// 集群模式：框架自动注册 cluster_component 与 discovery
app := cherry.Configure(path, "game-1", false, cherry.Cluster)

// 单机模式：只注册 Actor 系统和自定义组件
app := cherry.Configure(path, "room-1", true, cherry.Standalone)

启动顺序

Startup() 内部按固定顺序注册组件，保证依赖正确：

  1. 集群组件（仅集群模式）
  2. 发现服务组件（仅集群模式）
  3. Actor 系统组件
  4. 你通过 app.Register() 注册的自定义组件

所以自定义组件总能拿到可用的 Cluster()、Discovery()、ActorSystem()。

两个入口 ​

框架提供两层入口，常用的是第一个：

入口返回说明
cherry.Configure(profileFilePath, nodeID, isFrontend, mode)*AppBuilder推荐。先收集组件，Startup() 时统一注册，顺序可控
cherry.NewApp(profileFilePath, nodeID, isFrontend, mode)*Application直接拿到 Application，需要自己 Register 并调用 Startup

AppBuilder 内部持有一个 Application，它的 Startup() 保证按「集群 → 发现 → Actor 系统 → 自定义组件」的顺序注册，所以业务代码里的 Cluster()、Discovery()、ActorSystem() 一定可用。除非有特殊需求，否则用 Configure。

查找组件 ​

go
comp := app.Find("gorm_component")        // 按名称查找，返回 IComponent
db, ok := comp.(*cherryGORM.Component)    // 断言成具体类型

框架内置的组件都导出了名称常量，建议用常量而不是字面量：

go
app.Find(cherryGORM.Name)      // "gorm_component"
app.Find(cherryMongo.Name)     // "mongo_component"
app.Find(cherryDataConfig.Name)
