多节点集群 ​

一个完整的五节点游戏服务端骨架，适合作为实际项目的起点。涵盖节点发现、跨节点 RPC、网关路由、顶号处理、账号体系等生产环境的常见结构。

  • 五个节点：master / center / web / gate / game
  • 通信方式：节点间基于 NATS
  • 两种客户端：Go 实现的压测机器人（TCP + protobuf）和 H5 页面（WebSocket + protobuf）
  • 不使用数据库：进程重启会还原所有数据

须知 ​

  • 示例中没有接入数据库，重启即还原
  • 推荐在 demo_chat 之后阅读——先把 Actor 和路由的基本概念搞清楚
  • 欢迎加群讨论（QQ 群：191651647）

要求 ​

  • Go >= 1.24
  • nats.io >= 2.0

获取代码 ​

bash
git clone https://github.com/cherry-game/examples.git
cd examples

架构 ​

                        ┌──────────┐
                        │  master  │  发现服务：记录"集群里有哪些节点"
                        └────┬─────┘  （只有它，其他节点向它注册 + 发心跳）
                             │ nats
        ┌──────────┬─────────┼─────────┬──────────┐
        │          │         │         │          │
   ┌────▼───┐ ┌────▼───┐ ┌───▼────┐ ┌──▼───┐ ┌────▼────┐
   │ center │ │  web   │ │  gate  │ │ game │ │  game   │
   └────────┘ └───┬────┘ └───┬────┘ └──────┘ └─────────┘
   全局唯一业务   http接口   客户端连接   游戏逻辑（可横向扩展）
   账号 uid 分配  h5页面     消息路由
                     ▲          ▲
                     │ http     │ tcp / websocket
                  ┌──┴──────────┴──┐
                  │  h5 客户端 / 压测机器人  │
                  └────────────────┘

节点职责 ​

节点nodeType职责可横向扩展
mastermaster发现服务，维护全集群节点列表，不处理业务否
centercenter中心服，处理全局唯一事务（账号、uid 分配）否
webwebHTTP 服务，注册/登录/区服列表，托管 H5 客户端是
gategate网关，管理客户端连接、消息路由与转发是
gamegame游戏逻辑服，玩家的实际业务逻辑是

一条消息的完整旅程 ​

以客户端「进入角色」为例，把上面这些节点串起来看：

客户端 ──① GET /login ─────────────▶ web      换取 token
       ◀──── token, 区服列表 ───────

客户端 ──② tcp/ws 连接 ────────────▶ gate     建 Agent + 子 actor(sid)
       ── gate.user.login(token) ─▶ gate     ActorAgent.login()
                                              校验 token → 向 center 换 uid → Bind
       ◀──── LoginResponse ────────

客户端 ──③ game.player.enter ──────▶ gate     route 第一段是 game，不是本节点
                                    gate ──转发(nats)──▶ game.ActorPlayers
                                                         └ 按 uid 找到 player 子 actor
       ◀──── 响应 ──────────────────

网关不处理游戏逻辑

gate 只做校验和转发。真正处理业务的是 game 节点上那个以玩家 uid 命名的子 Actor，路径形如 10001.player.<uid>。

这也是为什么 gate 和 game 都能横向扩展——扩容任意一侧都不影响另一侧的职责。

启动步骤 ​

1. 启动 NATS ​

NATS 是节点间的消息中间件，所有节点都基于它通信。

  • Windows：运行 3rd/nats-server/nats-server.exe
  • Mac：nats-server

看到下面的输出就代表启动成功：

Listening for client connections on 0.0.0.0:4222

正式环境

生产环境请部署 NATS 集群而不是单机。安装方式见 安装 NATS。

2. 启动节点 ​

五个节点类型都从同一个入口启动，靠第一个命令行参数区分。工作目录必须是 demo_cluster/nodes：

bash
cd demo_cluster/nodes

go run . master --path=../../config/demo-cluster.json --node=gc-master
go run . center --path=../../config/demo-cluster.json --node=gc-center
go run . web    --path=../../config/demo-cluster.json --node=gc-web-1
go run . gate   --path=../../config/demo-cluster.json --node=gc-gate-1
go run . game   --path=../../config/demo-cluster.json --node=10001

每个节点两个公共参数：

参数默认值说明
--path../../config/demo-cluster.jsonprofile 配置文件路径
--node必填本节点的 nodeID，必须能在配置里找到

还有 version 子命令可以查看当前使用的框架版本：

bash
go run . version

启动顺序

master 必须最先启动，center 次之。gate / game / web 都注册了 check_center 组件，会等 center 就绪后才继续启动——顺序错了会卡住或报 center node connect fail。

3. 用 IDE 调试 ​

仓库的 .vscode/launch.json 已经配好了五个调试项，直接启动 gc-master、gc-center、gc-web-1、gc-gate-1、gc-game-10001 即可。

测试 ​

H5 客户端 ​

浏览器打开 http://127.0.0.1:8081，按界面提示操作。

流程是：注册账号 → 登录拿 token → 连接 gate（WebSocket）→ gate.user.login → 选择/创建/进入角色。

8081 端口冲突

demo_chat 的 HTTP 服务也用 8081，两个示例不要同时启动。web 节点报 bind: Only one usage of each socket address 通常就是这个原因。

压测机器人 ​

bash
cd demo_cluster/robot_client
go run .

机器人走 TCP + protobuf，流程是：注册账号 → 登录拿 token → 连接网关 → 用户登录 → 查看角色 → 创建角色 → 进入角色。

主要参数在 robot_client/main.go 顶部：

参数默认值说明
maxRobotNum5000机器人数量，首次试跑建议改成几十个
urlhttp://127.0.0.1:8081web 节点地址
addr127.0.0.1:10011网关 TCP 地址
serverId10001测试的游戏服 id
pid2126001测试的 SDK 包 id

跑起来后可以在 game 节点的控制台看到在线人数。机器人跑完不会退出，按 Ctrl+C 结束。

配置 ​

配置文件在 config/demo-cluster.json。

发现服务 ​

json
{
    "cluster": {
        "discovery": { "mode": "nats" },
        "nats": {
            "prefix": "node",
            "master_node_id": "gc-master",
            "address": "nats://127.0.0.1:4222"
        }
    }
}

master_node_id 必须与跑 master 的节点 node_id 一致。正式环境也可以切换成 etcd 模式。

节点配置 ​

json
{
    "node": {
        "master": [
            { "node_id": "gc-master", "enabled": true,
              "__settings__": { "ref_logger": "master_log" } }
        ],
        "center": [
            { "node_id": "gc-center", "enabled": true,
              "__settings__": { "ref_logger": "center_log" } }
        ],
        "gate": [
            { "node_id": "^gc-gate-\\d+$", "address": ":10010", "enabled": true,
              "__settings__": {
                  "ref_logger": "gate_log",
                  "db_id_list": { "game_db_id": "game_db_1" }
              } }
        ],
        "web": [
            { "node_id": "gc-web-1", "address": "127.0.0.1:8081", "enabled": true }
        ],
        "game": [
            { "node_id": "^\\d+$", "enabled": true,
              "__settings__": { "ref_logger": "game_log" } }
        ]
    }
}

用正则做横向扩展

gate 的 node_id 写成 ^gc-gate-\d+$、game 写成 ^\d+$，都是正则。加机器时不用改配置，直接用新的 --node 参数启动即可，框架会匹配到同一个配置块。

game 节点的 nodeID 必须是纯数字——它被用作雪花算法的节点号。

enabled 字段目前不生效

node 段里每个节点都有个 enabled 字段，但框架读了却没有使用。设成 false 并不会关掉这个节点，别依赖它来控制节点启停。

注意 db 段里的开关字段拼写不同，叫 enable（没有 d）。两者由不同代码读取，写错不会报错，只会静默使用默认值。

策划配表 ​

配表放在 config/data/，包含区服、SDK、错误码、掉落、玩家初始化等配置。加载方式见 data-config 组件。

gate 节点 ​

网关面向客户端，管理连接、路由和转发。它同时监听两个端口：

端口协议用途
:10010WebSocketH5 客户端
:10011TCP压测机器人

每条客户端连接会创建一个子 Actor：

go
agentActor.SetOnNewAgent(func(newAgent *pomelo.Agent) {
	childActor := &ActorAgent{}
	newAgent.AddOnClose(childActor.onSessionClose)
	agentActor.Child().Create(newAgent.SID(), childActor) // actorID == sid
})

跨节点路由由 onPomeloDataRoute 完成——如果目标节点类型不是自己，就通过 NATS 投递：

go
gameNodeRoute → pomelo.ClusterLocalDataRoute(agent, route, msg, serverId, targetPath)

路由有两道门禁：

  1. 未绑定 uid 的消息一律踢下线（登录消息 gate.user.login 除外）
  2. 未完成角色登录的连接只放行 game.player.select / create / enter 三个白名单方法

登录与顶号流程：校验 token → 查配表取 pid → 通过 CallWait 跨节点调用 center 分配 uid → 绑定 session → 顶掉旧连接 → 遍历发现服务通知其它 gate。

game 节点 ​

游戏逻辑节点，isFrontend = false。注册了 cron、data-config、check_center、gorm 等组件。

核心是一个管理所有玩家的 Actor：

go
app.AddActors(&player.ActorPlayers{}) // actor 路径：10001.player

ActorPlayers 用 OnFindChild 动态创建每个玩家的子 Actor，子 Actor 注册 select / create / enter（Local）和 sessionClose（Remote）。

center 节点 ​

处理全局唯一的业务——账号注册、uid 分配等。其它节点通过跨节点 RPC 调用它：

go
app.ActorSystem().CallWait(sourcePath, targetPath, funcName, req, rsp)

目标节点 id 从发现服务里取：

go
Discovery().ListByType("center")

web 节点 ​

对外提供 HTTP 接口，可横向扩展。主要路由：

路由说明
GET /H5 客户端首页
GET /hello健康检查
GET /register账号注册
GET /login登录并返回 token
GET /server/list/:pid区服列表

check_center 组件 ​

一个自定义组件，作用是等 center 就绪后再让本节点继续启动。

从 v1.6.x 起，它改为后台协程每 2 秒轮询一次 rpcCenter.Ping，而不是在 Init 里同步等待——同步等待会和发现服务注册互相阻塞，导致死锁。

常用问题 ​

现象原因
net packet parser is nil.isFrontend = true 但没有设置网络解析器
center node connect failcenter 或 NATS 没启动，或启动顺序不对
集群互相发现不了master 必须最先启动
bind: Only one usage of each socket address8081 被占用，多半是 demo_chat 还在跑
go build -race 报 DATA RACE框架 v1.6.8 内部的两处已知竞争（Application.Running() 的非原子读、Member.LastAt 的无锁写），不在示例代码里
